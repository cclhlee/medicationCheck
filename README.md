# 第 10 週｜把第 9 週的資料庫接到網頁

## 主練習：接續你已建好的資料庫

先在第 9 週的資料庫確認「使用者」與「用藥時程」兩張表，以及一筆虛構的使用者資料。沿用第 9 週範例欄位：使用者ID、姓名、時程ID、藥名、劑量、服用時間、頻率。用藥時程表的使用者ID對應使用者表。自訂欄位或表名的小組，先比對 server.js 的查詢與自己的欄位。

1. 使用 Node.js 22.9 或更新版本。解壓縮練習包，在資料夾開啟終端機，第一次執行 `npm install`。
2. 複製 `.env.example` 為 `.env`，填入**既有**資料庫的 `DATABASE_URL`。桌機 PostgreSQL 使用本機的主機與資料庫名稱，Node.js 也在同一台電腦上執行。Supabase 使用既有專案 Connect 裡的 Session pooler 連線資訊與適用的 SSL 設定。
3. 表在 `public` 時沿用預設。若在其他 schema，在 `.env` 設定 `DB_SCHEMA`。連線密碼只放在後端環境變數。
4. 執行 `npm start`，開啟 http://localhost:3000。下拉選單會讀取既有使用者。選一位，按「查詢時程」，對照第 9 週已存在的資料。
5. 查詢成功後，新增一筆虛構時程，重新整理並查同一人。回原資料庫確認是同一筆資料。

既有資料庫可直接使用，無需匯入 seed.sql。請用課堂的虛構資料和有對應讀寫權限的帳號。

## 跟著瀏覽器追資料

- 網頁載入時，瀏覽器呼叫 `GET /api/users` 填入使用者下拉選單。
- 按查詢時，網頁呼叫 `GET /api/schedules?userId=...`。後端用 `pg` 直接連資料庫並回傳 JSON。200 和空陣列表示這位使用者沒有時程。
- 送出表單時，網頁呼叫 `POST /api/schedules`。後端驗證欄位後寫入資料庫，成功回傳 201。網頁再發一次 GET 更新清單。

## 備用：內建測試資料庫

若第 9 週的資料庫暫時連不上，執行 `npm run demo`，開啟同一網址。測試甲有一筆，測試丙沒有時程。這個模式使用內建 PGlite，重啟程式會還原測試資料。修好連線後，改用 `npm start` 接回原本的資料庫。
